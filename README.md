# opencode-skill-enforcer

Плагин для OpenCode V2. Держит скиллы и справочники в контексте, заставляет агента
ими пользоваться и напоминает следовать тому, что уже загружено.

## Три механизма

| Механизм | Где | Что делает |
| --- | --- | --- |
| Правило-напоминание | `session.hook("context")` | на каждом шаге модели добавляет в system короткое правило: база в контакте, сколько рабочих загружено, «сверься и добери» |
| Цепка | `session.hook("prompt")` | на входе сообщения кладёт в контекст базовый набор общения и/или скиллы по смыслу, а также куски из файлов-справочников |
| Счётчик | `tool.hook("execute.before")` | считает вызовы инструмента `skill`, чтобы правило знало, что уже загружено |

Правило работает всегда и не выключается. Цепка управляется опциями.

## Что включено по умолчанию

| Механизм | Дефолт движка | В конфиге пользователя |
| --- | --- | --- |
| Скиллы: база + добор | включено | включено |
| Справочники (`documents`) | выключено (`[]`) | включено (`~/AGENTS.md`) |
| Семантика (`docLlm`) | выключено (`false`) | включено |

То есть «из коробки» плагин цепляет только скиллы. Справочники и семантический добор
надо включать в конфиге.

## Установка

Глобально, в `~/.config/opencode/opencode.jsonc`:

```jsonc
{
  "plugins": [
    {
      "package": "~/Projects/GithubPublic/opencode-skill-enforcer",
      "options": {
        "minSkills": 3,
        "maxSkills": 5,
        "attachAlways": true,
        "attachPicked": true,
        "documents": [
          { "path": "~/AGENTS.md", "title": "AGENTS", "maxBlocks": 3, "maxChars": 6000 }
        ],
        "docLlm": true
      }
    }
  ]
}
```

Плагин подхватывается без перезапуска сервиса. Если не подхватился — `opencode service restart`.

## Опции

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| `minSkills` | `3` | Минимум рабочих скиллов на ход |
| `maxSkills` | `5` | Верхняя граница добора |
| `autoAttach` | `true` | Мастер-выключатель цепки; `false` — остаётся только правило |
| `attachAlways` | `true` | Цеплять базовый набор общения (`alwaysSkills`) |
| `attachPicked` | `true` | Цеплять добор по смыслу запроса |
| `alwaysSkills` | `["result-first","dialog-humanity","anti-ai-sludge"]` | База общения |
| `maxAttach` | `6` | Потолок на всё, что цепляется к одному промпту; `0` — без потолка |
| `padToMin` | `false` | Добивать добор до `minSkills` даже без совпадений |
| `defaultSkills` | `[]` | ID для добивки, когда включён `padToMin` |
| `minPromptChars` | `12` | Не трогать короткие реплики |
| `minScore` | `3` | Порог для скиллов: триггер весит 2, описание 1 |
| `documents` | `[]` | Файлы-справочники: строка-путь или объект `{path,title,maxBlocks,maxChars}` |
| `minDocScore` | `2` | Сколько разных слов промпта должно совпасть с абзацем |
| `maxDocBlocks` | `2` | Сколько попаданий из одного файла максимум |
| `docWindow` | `1` | На сколько соседних абзацев раздувать попадание |
| `maxDocChars` | `8000` | Потолок символов из одного файла за ход |
| `docLlm` | `false` | Семантический добор: если словесный поиск пуст, спросить модель |
| `docLlmMax` | `300` | Сколько абзацев показывать модели на выбор |
| `announce` | `false` | Писать события в stderr сервера |
| `logFile` | — | Писать события в файл (диагностика) |

### Режимы цепки

- всё (по умолчанию): база + добор;
- только база: `{ "attachAlways": true, "attachPicked": false }`;
- только напоминание, без тел: `{ "autoAttach": false }`.

## База общения

`alwaysSkills` — структура ответа (`result-first`), живой контакт (`dialog-humanity`),
язык без нейрослопа (`anti-ai-sludge`). Весит около 26 КБ, цепляется один раз за сессию,
дальше лежит в истории.

## Справочники

Файл режется на абзацы: единица кончается на пустой строке, но пустая строка внутри
блока кода (fenced ```` ``` ```` или `~~~`) и между пунктами одного списка кусок не рвёт.
Заголовок, стоящий отдельной строкой, приклеивается к следующему абзацу как подпись.

Поиск идёт по телу текста: грубый стемминг (слова от 6 букв → первые 5, короткие
латинские `mcp`/`api` целиком) плюс вес редкости (IDF). Порог — сколько разных слов
промпта совпало (`minDocScore`). Попадание раздувается на соседние абзацы (`docWindow`),
соседние окна склеиваются, обрезка идёт по границе абзаца.

Кусок вставляется в текст сообщения с меткой:

```text
<!-- skill-enforcer:doc-context -->
[AGENTS — «Название раздела»]
…текст…
```

Перед вставкой плагин смотрит последние сообщения сессии: если кусок там уже есть —
пропускает; если выпал (например, после сжатия истории) — подставит снова. Плюс
durable-фолбэк в `ctx.storage` (ключ `injected/<sessionID>`) на случай, если историю
не прочитать. Кэш разобранных файлов — по `mtime`, при правке файл перечитывается.

`docLlm: true` добавляет семантический добор: когда словесный поиск не дал ничего,
плагин показывает модели список абзацев и просит номера нужных. Это лишний вызов
модели на промахе.

## Как устроено

Один файл — `index.ts`.

```text
readOptions                 разбор опций
expandHome                  "~/x" → домашний каталог
stemWords / words           токены для поиска
splitDoc                    файл → абзацы
picksFromHits               попадания → куски (окно, склейка)
selectBlocks                словесный поиск (IDF)
llmSelect / askModel        семантический добор
renderRule                  текст правила для system
setup                       карты сессии, docsFor, хуки
```

Состояние держится в памяти ключами по `sessionID` (что в контакте, что читалось в
ходу), плюс `ctx.storage` для списка подставленных кусков. Вставленный текст живёт в
истории сессии, поэтому новая сессия (`/new`) начинает с чистого листа.

## Диагностика

События (`loaded`, `attached`, `injected rule`, `doc`, `doc-inject`, `doc llm`)
пишутся в `logFile` или в файл из `SKILL_ENFORCER_DEBUG`:

```bash
SKILL_ENFORCER_DEBUG=/tmp/skill-enforcer.log opencode run -m <model> "тест"
tail -f /tmp/skill-enforcer.log
```

## Разработка

```bash
npm install
npx tsc --noEmit                                       # типы
bun build index.ts --target=bun --outfile=/tmp/se.js   # сборка
```
