# Внутреннее устройство

Один файл кода — `index.ts` в корне проекта.

## Карта функций

```text
readOptions                 разбор опций
expandHome                  "~/x" → домашний каталог
stemWords / words           токены для поиска
labelOf                     подпись куска (заголовок)
splitDoc                    файл → абзацы
clipBlock                   обрезка куска по границе абзаца
picksFromHits               попадания → куски (окно, склейка)
selectBlocks                словесный поиск (IDF)
llmSelect / askModel        семантический добор
renderRule                  текст правила для system
setup                       карты сессии, docsFor, хуки
```

## Скиллы

Добор по смыслу: секция «Загружай, когда:» и ID весят 2, остальное описание — 1.
Порог — `minScore`. База (`alwaysSkills`) цепляется один раз за сессию: если скилл уже
в контакте, повторно не грузим.

### Брокер

Когда словесного отбора не хватает (скиллов меньше `minSkills` или у справочника не
нашлось ни одного блока), плагин делает **один** вызов модели на оба источника сразу
(`skillLlm` / `docLlm`). Модель отвечает двумя строками: `SKILLS: ...` и `DOCS: D<док>.<абзац>`.
Кандидатов-абзацев дают до `docLlmMax`, кандидатов-скиллов — только тех, что ещё не в
контексте. Запрос идёт через `ctx.session.generate`, модель берётся из сессии. Если
словесный отбор справился сам — вызова нет. Время вызова пишется в лог строкой `broker:
... <мс>`.

Правило в system каждый шаг сообщает: что за база в контакте, сколько рабочих загружено
в текущем ходу, что уже читается.

## Справочники

Файл режется на **блоки по размеру**: абзацы копятся, пока блок не станет весомым
(цель 600–1200 символов). Новый блок начинается у заголовка, если минимум уже набран.
Пустая строка внутри кода (fenced ` ``` ` или `~~~`) и между пунктами одного списка
кусок не рвёт. Заголовок отдельной строкой приклеивается к следующему абзацу.

Так AGENTS.md превращается в ~16 нормальных кусков вместо сотни огрызков по 60 символов.

Поиск идёт по телу текста: стемминг (слова от 6 букв → первые 5, короткие латинские
`mcp`/`api` целиком) плюс вес редкости (IDF). Порог — `minDocScore`. Попадание
раздувается на соседние абзацы (`docWindow`), соседние окна склеиваются, обрезка — по
границе абзаца.

У каждого куска в подписи короткий хэш текста. Секцию правишь — хэш меняется, и кусок
приезжает заново; текст тот же — не дублируется.

Вставка помечается в тексте сообщения:

```text
<!-- skill-enforcer:doc-context -->
[AGENTS — «Название раздела» #1cplcqp]
…текст…
```

Перед вставкой плагин читает последние сообщения сессии и решает по факту: скилл и кусок
справочника, которые уже в контексте, повторно не подкладываются; если выпали (например,
после сжатия истории) — вернутся. Разобранные файлы кэшируются по `mtime`.

`docLlm: true` включает семантический добор (см. «Брокер»): когда словесный поиск не
дал ничего, модель выбирает абзацы вместе со скиллами — одним вызовом на оба источника.

## Состояние

Всё держится в памяти, ключи по `sessionID`:

```text
inContact       что уже в контакте (база + рабочие)
turnTask        рабочие скиллы, попавшие в контекст в текущем ходу
docCache        путь → разобранные абзацы (кэш по mtime)
injectedDocs    куски, подставленные в этой сессии (фолбэк, когда история недоступна)
```

Вставленный текст живёт в истории сессии, поэтому `/new` (новая сессия) начинает с
чистого листа.
